# ESP32-1732S019 (1.9″ bar display, ESP32-S3) — hardware reference

Board directory `1732s019`. Written 2026-10-17 from the firmware, the repo
docs and the vendor pack in
[`doc/1.9inch_ESP32-1732S019/`](../1.9inch_ESP32-1732S019/). Labels used
below: **code** = what the firmware drives (verified to work on the bench
unit); **schematic** / **spec** / **demo** = vendor material only, not
exercised by Piano Coach unless stated.

## 1. Summary

The ESP32-1732S019 is a small (65 × 32 mm) display board from Shenzhen
Jingcai Intelligent (JCZN, jczn1688.com): an ESP32-S3-WROOM-1 N16R8
module, a 1.9″ 170×320 IPS TFT with an ST7789 controller on SPI, a CH340C
USB-UART bridge behind a USB-C socket, BOOT and RESET keys and two 12-pin
headers. There is no touch on the variant sold as `-N` (a touch FPC
footprint exists), no microSD slot, no audio, no battery charger and no
user LED. Piano Coach runs its **mini** UI on it in landscape (320×170),
keeps the whole song library (2449 songs) in a flash song pack and reaches
the piano over the S3's native BLE only.

## 4. Subsystems

### 4.1 Power

* USB-C VBUS → D1 1N5819W (Schottky) → `5V` net (schematic). The `5V`
  net is also on header P2 pin 1, downstream of the diode.
* Two AMS1117-3.3 LDOs from `5V`: **U3** makes `3.3V-ESP` for the module
  (and header P1 pin 11, the BOOT/EN pull-ups); **U1** makes `3.3V` for
  the LCD (VDD and backlight anode LEDA), the CH340C (VCC and V3) and the
  touch FPC. Each has a 0 Ω jumper (JP1 across U3, JP0 across U1) drawn
  from Vin to Vout; in the vendor PCB render they look like empty pads.
  Whether they are fitted on a real unit is unknown — fitted, they would
  tie 5 V to the 3.3 V rail, so leave them open.
* The USB-C CC1/CC2 pins (A5/B5) are drawn unconnected: there are no
  5.1 kΩ pull-downs, so a strict USB-C source (C-to-C cable, PD charger)
  may not turn VBUS on. Not tried on the bench (the bench unit has always
  been powered from a PC port); inference from the schematic.
* No battery connector, charger, fuel gauge or power latch. "Shut down"
  in the firmware is deep sleep (`CAPS.power_latch = false`), §7.
* `init_power()` does nothing: the radio is on-chip and no rail is
  switchable.

### 4.2 USB

* The USB-C data pins go **only to the CH340C** (nets `USB-DP` / `USB-DN`
  on A6/B6 and A7/B7). The board is a USB-UART device, not a USB host
  or native USB device; Piano Coach cannot use USB-MIDI here
  (`HAS=` is empty, `CAPS.usb_midi = false`).
* The S3's native USB pins GPIO19 (D−) / GPIO20 (D+) carry the net
  names `USB-PWR-DM` / `USB-PWR-DP`, which differ from the connector's
  nets: per the schematic they only reach header P1 pins 2 / 1. The
  generated sdkconfig (ESP-IDF default) has
  `CONFIG_ESP_CONSOLE_SECONDARY_USB_SERIAL_JTAG=y`; that secondary
  console is unreachable unless someone wires a USB cable to P1.
* CH340C: crystal-less, powered from `3.3V` (VCC pin 16 and V3 pin 4 on
  the same rail). TXD → U0RXD, RXD → U0TXD. DTR# and RTS# drive the
  standard two-transistor auto-download circuit (T1/T2 S9013, 10 kΩ base
  resistors) onto IO0 and EN, so espflash can reset and enter download
  mode without touching the keys.

LCD connector P3 pinout (schematic): 1 GND, 2 LEDK, 3 LEDA (3.3V), 4 VDD
(3.3V), 5 GND, 6 GND, 7 DC, 8 CS, 9 SCL, 10 SDA, 11 RST, 12 GND.

→ reset → init → invert → swap_xy → mirror → gap → clear to background
in 4-line bands → display on → backlight PWM set up.

### 4.4 Buttons

* **BOOT** (GPIO0, active low, external 10 kΩ pull-up R2; the firmware
  also enables the internal pull-up). It is the mini UI's only key,
  decoded in `board/key.rs`: debounce 25 ms, tap reported after a 280 ms
  double-tap window, double tap, hold ≥ 600 ms. Polled from the UI loop
  (every frame, ≤ 40 ms). `CAPS.key_hint = "tap ›  2× ‹  hold OK"`.
* **RESET** (EN). Resets the chip; also the other way out of deep sleep.
* Holding BOOT while pressing/releasing RESET enters the ROM download
  mode (GPIO0 strapping); normally unnecessary because of the CH340C
  auto-reset.

### 4.5 LEDs

No user LED on the schematic or the PCB render. The only LED is the LCD
backlight (§4.3). Note the vendor pinout PNG
(`5-Schematic/ESP32-S3-WROOM-1 Pin definition.png`) is Espressif's
generic DevKitC-1 diagram — its "RGB@IO38", CP2102 and two USB ports do
**not** exist on this board.

### 4.6 Touch (not fitted)

The schematic has a 6-pin 0.5 mm FPC "TP-C" for a capacitive touch
panel: 1 GND, 2 CTP_SDA → GPIO9 (R6 4.7 kΩ pull-up), 3 CTP_SCL → GPIO46
(R7 pull-up, "NC"), 4 CTP_RST → GPIO3, 5 CTP_INT → GPIO8, 6 → 3.3V.
The controller type is not named in the schematic (the demo pack ships a
GT911 Arduino library, but no sketch for this board uses it — unknown).
The bench unit is the `-N` (no touch) SKU: `CAPS.touch = false`,
`touch_point()` returns `None`.

### 4.7 Audio amplifier (not on the board)

The vendor pack contains a MAX98357A/B datasheet (file name
`AX98357AETE T_2021-01-06.PDF`; I²S-input class-D mono amplifier, no
MCLK, no I²C) and an Arduino sketch `6_1_Audio_test` that streams MP3s
with `I2S_DOUT 17`, `I2S_BCLK 19`, `I2S_LRC 18`. **Neither the V1.0
schematic nor the PCB render has an amplifier or speaker connector.**
The sketch and datasheet are most likely shared across JCZN boards, or
assume an external MAX98357A module wired to header P1 (GPIO17/18/19).
Note GPIO19 is also the native USB D− net. Piano Coach has no speaker
on this board (`HAS=` without `speaker`); the speaker synth is not
compiled in.

### 4.8 Storage

* No microSD (see §8 for the spec's claim). Songs live in the `songs`
  flash partition as a **song pack** (`piano-core/src/songpack.rs`):
  header, 28-byte-per-entry tree index, names, zlib-compressed MIDI.
  `src/songs.rs` finds the partition by name, memory-maps it (no RAM for
  the index), checks the index CRC and inflates one song at a time into
  PSRAM. Pack songs load as virtual paths `/pack/<index>`.
* Current pack: all **2449 songs**, `target/1732s019/songs.bin` =
  9,347,030 bytes (8.9 MB) of the 12,517,376-byte partition;
  `SONGPACK_ARGS="--max-bytes 11.9M"` (no note limit).
* `boards/1732s019/glyphs.slint` is generated by `tools/songs.sh build`:
  1890 distinct characters of the packed names. Rebuild the firmware when
  it changes (the fonts are pre-rendered SDF glyphs).
* NVS (`nvs` partition) holds prefs (namespace `piano`, i32 values),
  best scores, and NimBLE bonds (`CONFIG_BT_NIMBLE_NVS_PERSIST=y`).

### 4.9 Radio

* ESP32-S3 on-chip Wi-Fi 802.11 b/g/n and Bluetooth LE 5 (Espressif
  pinout sheet; the vendor user manual's "Classic Bluetooth/BLE 4.2" is
  wrong for an S3). PCB antenna on the module (WROOM-1, not -1U).
* Piano Coach uses BLE only: native controller + NimBLE host, central
  and observer roles only, one connection, preferred ATT MTU 260,
  NimBLE memory from PSRAM (`BT_NIMBLE_MEM_ALLOC_MODE_EXTERNAL`), host
  task stack 8 KB. `bt_controller_start()` is a no-op
  (`nimble_port_init` brings the native controller up).
* This board is **not** built with `ble_relaxed` (`build.rs` sets it only
  for headless boards and `MCU=esp32`), so it keeps the piano's own
  10 ms interval / 500 ms supervision timeout and writes with
  `WRITE_GAP = 0`. NimBLE host flow control is off
  (`# CONFIG_BT_NIMBLE_HS_FLOW_CTRL is not set`) and
  `CONFIG_BT_NIMBLE_ACL_BUF_COUNT=24` — both ESP-IDF defaults seen in the
  generated sdkconfig, not set in `sdkconfig.defaults`.
* Wi-Fi is not used by the mini UI.

### 4.10 Other connectors

Only the USB-C, P1/P2 headers (§3), the LCD connector P3 (12-pin) and
the unpopulated touch FPC. Four mounting holes; hole spacing 59.0 ×
26.0 mm, board 65.0 × 32.0 mm, corner radius 1.6 mm (spec p.6).

## 6. Build, flash, console

From `firmware/piano-coach/`:

```bash
# Toolchain once: espup install --name esp198 --toolchain-version 1.98.1.0 --targets esp32s3 --std
tools/board.sh 1732s019 build --release                 # first build compiles ESP-IDF (10+ min)
tools/songs.sh 1732s019 build                           # pack + boards/1732s019/glyphs.slint
tools/songs.sh 1732s019 flash --port /dev/ttyUSB0 --baud 921600   # writes songs.bin at 0x410000
tools/board.sh 1732s019 run --release -- --port /dev/ttyUSB0      # flash app + monitor (blocks)
```

* `tools/board.sh` sources `boards/1732s019/board.env` and sets `MCU=esp32s3`,
  `ESP_IDF_VERSION=v5.5.3`, the sdkconfig defaults, the components file,
  `ESP_IDF_SDKCONFIG=sdkconfig.1732s019`, `CARGO_TARGET_DIR=target/1732s019`,
  the board partition table, and runs
  `cargo +esp198 … --target xtensa-esp32s3-espidf --no-default-features --features board-1732s019`
  with `LIBCLANG_PATH` from the esp198 toolchain. ESP-IDF tools are shared
  from `/home/nws/w/rust/herdline/clients/tab5/.embuild/espressif`.
* `run` uses the cargo runner `./flash.sh` → `espflash flash --monitor
  --bootloader … --partition-table … <elf>` with the bootloader and
  partition table from the same ESP-IDF build (`FLASHER=espflash`).
* Direct espflash (what the sessions used), `T=target/1732s019/xtensa-esp32s3-espidf/release`:
  `espflash flash --chip esp32s3 --port /dev/ttyUSB0 --baud 921600 --bootloader T/bootloader.bin --partition-table T/partition-table.bin T/piano-coach`.
  Flashing the app does not touch NVS or the song pack; `songs.sh flash`
  does not touch the app.
* If `glyphs.slint` changed after `songs.sh build`, rebuild the firmware.
* **Port identification**: the CH340C appears as `/dev/ttyUSB*`; other
  boards on the bench also use CH340/CP210x on `ttyUSB*`, so check with
  `udevadm info -q property -n /dev/ttyUSBx | grep ID_SERIAL` or
  `espflash board-info --port …` before flashing.
* **Download mode / reset**: automatic through DTR/RTS (§4.2). Manual
  fallback: hold BOOT, press and release RESET, release BOOT.
* **Console**: UART0 at 115200 through the CH340C. When reading logs
  with pyserial, open the port with DTR and RTS **false** — the
  auto-reset transistors otherwise reset the board or hold it in
  download mode; reset deliberately with an RTS pulse.
* **Set a pref from the PC**: AGENTS.md recipe (NVS image written at the
  `nvs` offset 0x9000, size 0x6000). It replaces all prefs and BLE bonds.
* UI preview on the PC: `tests/mini_preview` renders the bar screens.

## 7. Piano Coach support

* **UI class**: `mini` (`ui_mini.rs`, `ui/mini/app.slint`), 320×170 bar,
  scale 1.0. Library wheel, song menu (Learn / Follow / Listen, hands,
  tempo), play screen, settings (easy mode, hint off on hit,
  accompaniment, follow lead, brightness, Light all keys, All LEDs off,
  about, Sleep). No Mirror display item on this board.
* **Transport**: BLE only, auto-connects to `GZUT-MIDI`. `CAPS`:
  `backlight: true`, `power_latch: false`, `usb_midi: false`,
  `ble_midi: true`, `buttons: true`, `touch: false`,
  `wake_hint: "BOOT or RESET"`.
* **Songs**: flash pack, all 2449 songs.
* **Sleep / power off** (`power_off`): backlight off, wait until BOOT is
  released (else it would wake at once), `esp_sleep_enable_ext0_wakeup(GPIO0, 0)`,
  deep sleep. BOOT or RESET wakes (a reboot).
* **Boot**: Follow mode with a random 儿时回忆 song that starts when the
  piano connects (all boards).
* **Piano-key remote**: every key from `piano_core::controls` works

## 8. Quirks & lessons learned

* **Spec mislabels GPIO13 as "MISO"** (spec p.5 drawing). It is the
  panel's data input (schematic `TFT_SDI` → P3 "SDA"; demos pass it as
  MOSI). The firmware uses it as MOSI and has no MISO, so the panel ID
  cannot be read back.
* **Spec claims a "TF card slot"**; the V1.0 schematic and the PCB
  render have none. The firmware treats the board as card-less.
* **The 170-pixel side is offset by 35** in the ST7789's 240-column RAM
  (`set_gap(0, 35)`; the vendor demos use column offset 35 too). The
  panel also needs colour inversion (IPS). Both are in the code and
  verified ("display orientation and colours ✔").
* **Colour order is RGB** here (the round GC9A01 board is BGR); the code
  is the reference.
* **Orientation is identical across units** — no per-unit mirror pref
  is needed (unlike the ESP32-2424S012C).
* The vendor's section label "Resistive touch" in the schematic sits
  over the USB/CH340 block, and the pin-definition PNG is Espressif's
  DevKitC-1 — the vendor pack is partly template material; trust the
  schematic drawing itself and the code.
* The vendor user manual says to "reset the power" to re-enter flashing
  mode; with the CH340C auto-reset that is not needed for espflash.
* **Deep sleep wake**: wait for BOOT to be released before arming ext0,
  otherwise the board wakes immediately.
* BLE under two-way traffic is fine on this S3 without `ble_relaxed`
  (contrast: the original ESP32 boards needed host flow control off and
  a relaxed link).
* Only one BLE central can hold the piano: power off the other boards
  and tablets when testing this one.
